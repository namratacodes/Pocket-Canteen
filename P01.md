# Phase 1 — Foundation, Design System & Authentication

> **Project context (all you need to know):** Pocket Canteen is a campus food pre-ordering platform covering 5 canteens. There are three user roles. **Students** order and pay from their phone and collect food with a token (e.g. `A-14`) and a private 4-digit pickup code. **Staff** run a live kitchen board. **Admins** onboard canteens and handle settlements. Member 1 builds the Node/Express + PostgreSQL backend with Socket.io. Member 3 builds the ML service for ETA prediction and analytics. **Member 2 (you) builds the single React web app `apps/web/` that serves all three roles.**
>
> **This phase builds the skeleton that every screen sits on.** When it's done, each role can log in and land in its own empty, styled shell.

---

## 1. Goal & Scope

**In scope**
- Vite + React + TypeScript project with Tailwind and shadcn/ui
- Design tokens (colours, fonts, spacing) and a shared component kit
- Routing for `/student`, `/staff`, `/admin` with layout shells and role guards
- Student login (phone + OTP) and staff/admin login (email + password)
- Token handling: access token in memory, refresh token in a cookie, silent refresh
- `apiClient` (typed fetch wrapper with error normalisation)
- `socketClient` (authenticated Socket.io singleton with connection status)
- MSW mock infrastructure, so the app runs with no backend

**Out of scope:** any business screen (menus, orders, board, admin tables). Those belong to Phases 2–5.

## 5. Data Contract for This Phase

```ts
// types/index.ts (baseline; later phases add to it)
export type Role = 'student' | 'staff' | 'admin';
export type OrderStatus = 'placed' | 'queued' | 'preparing' | 'ready' | 'completed' | 'cancelled';
export type PaymentStatus = 'pending' | 'paid' | 'failed' | 'refunded_to_wallet';

export interface User {
  id: string; name: string; phone: string; email?: string;
  role: Role;
  canteenId: string | null;      // set for staff only
  canteenName?: string;
  mustChangePassword?: boolean;
}
export interface AuthResponse { accessToken: string; user: User; }
export interface ApiErrorBody { error: { code: string; message: string; details?: Record<string, unknown> } }
```

| Endpoint | Request | Response | Errors |
|---|---|---|---|
| `POST /auth/otp/send` | `{ phone: "+919876543210" }` | `{ sent: true, resendAfterSec: 30 }` | `429 RATE_LIMITED` (`Retry-After` header) |
| `POST /auth/otp/verify` | `{ phone, otp: "123456" }` | `AuthResponse` (+ sets refresh cookie) | `400 OTP_INVALID`, `410 OTP_EXPIRED`, `429` |
| `POST /auth/login` | `{ email, password }` | `AuthResponse` | `401 INVALID_CREDENTIALS`, `403 ACCOUNT_DISABLED`, `429` |
| `POST /auth/refresh` | (cookie) | `AuthResponse` | `401` → logged out |
| `POST /auth/logout` | – | `204` | – |
| `PATCH /auth/password` | `{ currentPassword, newPassword }` | `204` | `400 WEAK_PASSWORD` |
| `PATCH /me` | `{ name }` | `User` | – |

**Socket handshake:** `io(VITE_WS_URL, { auth: { token } })`. The server rejects with `connect_error` message `"unauthorized"` when the token is invalid.

## 6. Core Implementation

### 6.1 `authStore` (Zustand, **not persisted**; the token lives in memory only)

```ts
interface AuthState {
  status: 'booting' | 'authenticated' | 'anonymous';
  accessToken: string | null;
  user: User | null;
  setSession(r: AuthResponse): void;
  clear(): void;
}
```

### 6.2 `apiClient`
```ts
export class ApiError extends Error {
  constructor(public status: number, public code: string, message: string, public details?: any) { super(message); }
}
let refreshing: Promise<string | null> | null = null;   // single-flight

export async function api<T>(path: string, init: RequestInit & { json?: unknown } = {}): Promise<T> {
  const doFetch = (token?: string | null) => fetch(`${import.meta.env.VITE_API_URL}${path}`, {
    ...init,
    credentials: 'include',
    headers: { 'Content-Type': 'application/json', ...(token && { Authorization: `Bearer ${token}` }), ...init.headers },
    body: init.json !== undefined ? JSON.stringify(init.json) : init.body,
  });
  let res = await doFetch(useAuth.getState().accessToken);
  if (res.status === 401 && !path.startsWith('/auth/')) {
    refreshing ??= refreshToken().finally(() => (refreshing = null));
    const newToken = await refreshing;
    if (!newToken) { useAuth.getState().clear(); throw new ApiError(401, 'UNAUTHENTICATED', 'Session expired'); }
    res = await doFetch(newToken);
  }
  if (!res.ok) {
    const body = await res.json().catch(() => null) as ApiErrorBody | null;
    throw new ApiError(res.status, body?.error.code ?? 'UNKNOWN', body?.error.message ?? res.statusText, body?.error.details);
  }
  return res.status === 204 ? (undefined as T) : res.json();
}
```
- Network failure (a `TypeError` from fetch) → rethrow as `ApiError(0,'NETWORK','Can't reach server')`.
- `queryClient` defaults: `retry: (n, e) => e.status >= 500 && n < 2`, `staleTime: 30_000`, `refetchOnWindowFocus: true`.

### 6.3 Auth bootstrap (in `providers.tsx`)
1. App mounts → `status='booting'` → render `FullPageSpinner`.
2. Call `POST /auth/refresh`. On success → `setSession`, on failure → `status='anonymous'`.
3. If authenticated → `socketClient.connect()`.

### 6.4 `socketClient`
```ts
export const socket = io(import.meta.env.VITE_WS_URL, {
  autoConnect: false, transports: ['websocket'],
  auth: (cb) => cb({ token: useAuth.getState().accessToken }),
  reconnectionDelay: 1000, reconnectionDelayMax: 10000,
});
const rooms = new Set<string>();
export const joinRoom = (r: string) => { rooms.add(r); socket.connected && socket.emit('room:join', { room: r }); };
export const leaveRoom = (r: string) => { rooms.delete(r); socket.emit('room:leave', { room: r }); };
socket.on('connect', () => { rooms.forEach(r => socket.emit('room:join', { room: r })); connection.set('connected'); queryClient.invalidateQueries(); });
socket.on('disconnect', () => connection.set('reconnecting'));
socket.on('connect_error', async (e) => { if (e.message === 'unauthorized') { await refreshToken(); socket.connect(); } });
window.addEventListener('offline', () => connection.set('offline'));
```
`useSocketEvent(event, handler)` is a hook that subscribes on mount and unsubscribes on unmount, keeping the handler in a ref to avoid stale closures.
In mock mode, export a `mockSocket` with the same `on/off/emit` API instead (see §9).

### 6.5 Routing (`router.tsx`)
```text
/                    RoleRedirect → /student | /staff/board | /admin | /login
/login               StudentLoginPage
/staff/login         StaffLoginPage role="staff"
/admin/login         StaffLoginPage role="admin"
/change-password     ChangePasswordPage
/student/*           <RequireRole role="student"><StudentShell/></RequireRole>   (lazy)
/staff/*             <RequireRole role="staff"><StaffShell/></RequireRole>       (lazy)
/admin/*             <RequireRole role="admin"><AdminShell/></RequireRole>       (lazy)
/403, *              Forbidden, NotFound
```
`RequireRole` logic: booting → spinner · anonymous → redirect to that role's login with `?next=` · wrong role → `/403` · `mustChangePassword` → `/change-password`.
Each role subtree is loaded with `React.lazy`, so a student never downloads staff or admin code.

## 7. Screens

### 7.1 Student Login (`/login`)
```text
Step 1                              Step 2
┌──────────────────────────┐        ┌──────────────────────────┐
│   🍽 Pocket Canteen       │        │ Enter the code sent to    │
│ Skip the queue.           │        │ +91 98765 43210  (Edit)   │
│                           │        │ [_][_][_][_][_][_]        │
│ [+91][98765 43210      ]  │   →    │ Resend in 0:28            │
│ [     Send OTP        ]   │        │ [      Verify        ]    │
│ Staff? Log in here →      │        └──────────────────────────┘
└──────────────────────────┘
```
- zod: phone `/^[6-9]\d{9}$/`.
- OTP: shadcn `InputOTP`, `inputMode="numeric"`, `autoComplete="one-time-code"`, auto-submit on the 6th digit, paste supported.
- Resend timer comes from `resendAfterSec`. A 429 shows "Too many attempts, try in X min" using `Retry-After`.
- On success → if `user.name` is empty, show a "What should we call you?" step (`PATCH /me`) → navigate to `next` or `/student`.

### 7.2 Staff/Admin Login (`/staff/login`, `/admin/login`)
- Email and password (show/hide toggle), submit. Show an inline error for `INVALID_CREDENTIALS` and a toast for `ACCOUNT_DISABLED`.
- After login, verify the role matches the page; otherwise show "This account is not a staff account".
- `mustChangePassword` → `/change-password` (new password needs at least 8 characters with 1 number and 1 symbol, plus a confirm field).

### 7.3 Logout
`POST /auth/logout` → `authStore.clear()` → `socket.disconnect()` → `queryClient.clear()` → redirect to the role's login page.

## 10. Acceptance Criteria
- [ ] `npm run dev` with mocks → the login page renders. `npm run build` passes and `tsc --noEmit` shows 0 errors.
- [ ] A student logs in with OTP and lands in StudentShell. The bottom nav moves between 4 placeholder pages.
- [ ] Staff log in and land in the dark StaffShell showing their canteen name. Admin logs in and lands in AdminShell.
- [ ] A student visiting `/staff/board` gets `/403`. Visiting `/student` while logged out redirects to `/login?next=/student`, and after login you're returned there.
- [ ] A page refresh keeps the session (refresh flow). An expired access token is refreshed silently, and parallel requests trigger only **one** refresh.
- [ ] `ConnectionDot` turns orange when you toggle offline in DevTools and green when you go back online.
- [ ] Every shared component has a story or demo page at `/dev/components` (dev only).
- [ ] Lighthouse accessibility ≥ 95 on the login page.
