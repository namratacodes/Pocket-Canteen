# Phase 6 — PWA, Offline, Resilience, Quality & Deployment

> **Project context (all you need to know):** Pocket Canteen's frontend is one React (Vite + TypeScript + Tailwind) app with three areas: `/student` (mobile ordering, live order tracker, wallet), `/staff` (real-time kitchen board on tablets), and `/admin` (desktop portal). It talks to a REST API (`VITE_API_URL`) and a Socket.io server (`VITE_WS_URL`). Students rely on a **4-digit pickup code** kept in the browser's localStorage, and collect food at counters where **campus Wi-Fi is often poor**. Kitchen tablets run for whole shifts and **must never miss an order**. Payments use Razorpay Checkout.js.
>
> **This phase makes whatever has been built production-ready.** It covers installability, offline behaviour, reconnection, security, accessibility, performance, automated tests, and deployment. It's written to apply to **any subset** of screens that exist. Each section says what to do for each area.

### 3.2 Caching strategy
| Request | Strategy | Config | Reason |
|---|---|---|---|
| App shell, fonts, icons, sounds | Precache | build-time | Instant start, works offline, kitchen sounds always available |
| Menu/canteen images | `CacheFirst` | 7 days, 200 entries | Bandwidth |
| `GET /canteens`, `GET /canteens/:id/menu` | `StaleWhileRevalidate` | 1 day | Browse menus offline |
| `GET /orders/:id`, `GET /orders?scope=active`, `GET /wallet` | `NetworkFirst` | timeout 3s, 1 day | Fresh when online, last known state when offline |
| `GET /analytics/*`, `/admin/*` | `NetworkOnly` | – | No point in caching |
| **All POST/PATCH** (orders, payments, verify, cancel, toggles) | `NetworkOnly`, **no background sync** | – | Never replay money or verification actions later |
| `checkout.razorpay.com` | `NetworkOnly` | – | Third party |
| Socket.io | Bypassed | – | WebSocket |

### 3.3 Update prompt
```ts
// main.tsx
import { registerSW } from 'virtual:pwa-register';
const update = registerSW({ onNeedRefresh() { toast('New version available', { action: { label: 'Refresh', onClick: () => update(true) }, duration: Infinity }); } });
```

- **Kitchen board:** never auto-refresh. The toast waits, and the label reads "Refresh after the rush".
- During checkout (Razorpay open): suppress the toast until the user leaves checkout.

## 4. Offline UX
| Area | Offline behaviour |
|---|---|
| Global | `OfflineBanner` at the top: "You're offline — showing saved data". The `ConnectionDot` turns red |
| Canteen list / Menu | Cached data with a "Last updated 12:41 PM" note. **All ADD and Checkout buttons are disabled** with the text "Connect to order" |
| Cart | Fully works (localStorage) |
| Checkout | Blocked. If you go offline mid-request: "We couldn't confirm your order. Check *My orders* when you're back online before trying again" (prevents duplicates, alongside the idempotency key) |
| Order tracker | Last cached state + a "stale" tag. **The pickup code stays visible** (localStorage), the most important offline feature |
| Wallet | Cached balance + "may be outdated" |
| Kitchen board | Red full-width banner. Last known tickets stay visible. Action buttons are disabled with "Offline". Auto-recovers |
| Admin | "You're offline" empty state. Forms keep their drafts |

Test this with DevTools → Network → Offline, and with a real phone in airplane mode.

## 5. Real-Time Resilience (apply to every socket-driven screen)
1. **Reconnect with backoff:** `reconnectionDelay 1s → max 10s` with jitter (Socket.io default `randomizationFactor 0.5`).
2. **Rejoin rooms** on every `connect` (keep a `Set` of joined rooms).
3. **Catch up after reconnect:** `queryClient.invalidateQueries({ queryKey: ['orders'] })`, `['kitchen']`, `['wallet']`. The kitchen diff plays the new-order sound once for orders missed in between.
4. **Stale-event guard:** every handler ignores the payload if `payload.order.updatedAt < cached.updatedAt`.
5. **Dedupe** `order:new` by id.
6. **Polling fallback:** if disconnected for more than 10s → `refetchInterval` of 15s (student tracker) or 10s (kitchen board). It stops once connected.
7. **Visibility:** on `visibilitychange → visible`, refetch the active queries and check `socket.connected` (mobile browsers kill background sockets).
8. **Token expiry during the socket session:** on `connect_error 'unauthorized'`, refresh the token and reconnect.
9. **Chaos test script** (dev panel): "Kill socket 30s", "Server restart" (disconnect + reconnect), "Out-of-order events" (send an older update after a newer one), and "Duplicate event x3". Every case must end in a correct UI.

## 6. Error Handling & Monitoring
- `ErrorBoundary` per role shell: "Something went wrong · [Reload] [Go home]". Report to Sentry.
- A route-level `errorElement` (React Router) for loader and lazy-chunk failures. **Chunk load error** (after a deploy) → automatically reload once.
- Global `ApiError` toasts only for unexpected codes. Known codes are handled inline by their screens.
- **Sentry:** `Sentry.init({ dsn, tracesSampleRate: 0.1, beforeSend: scrub })`. The `scrub` function removes `code`, `pickupCode`, `otp`, `password`, `tempPassword` and phone numbers from breadcrumbs and payloads.
- Web Vitals (`web-vitals` package) are sent to Sentry or the console in dev.

## 7. Security Hardening
| Item | Action |
|---|---|
| Tokens | The access token stays in memory. The refresh token is an httpOnly Secure SameSite cookie (backend). No tokens in localStorage |
| Pickup code | localStorage only, deleted on completion, purged after 24h, never logged |
| XSS | ESLint `react/no-danger` set to error. No HTML from the API |
| CSP (`vercel.json` headers) | `default-src 'self'; script-src 'self' https://checkout.razorpay.com; frame-src https://api.razorpay.com https://checkout.razorpay.com; connect-src 'self' <API> <WS wss://> https://lumberjack.razorpay.com <sentry>; img-src 'self' data: https:; style-src 'self' 'unsafe-inline'; font-src 'self'` |
| Other headers | `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy: camera=(), microphone=(), geolocation=()` |
| Secrets | Only `VITE_*` public values in the frontend. The Razorpay **key secret never** reaches the client |
| Role guards | UX only. The backend enforces them. Lazy-load each role's code so it isn't exposed to the others |
| Dependencies | `npm audit --omit=dev` in CI. Renovate or Dependabot |

## 8. Accessibility (target: Lighthouse ≥ 95, axe has 0 serious issues)
- All interactive elements are reachable by keyboard with a visible focus ring (`focus-visible:ring-2 ring-brand`).
- Modals trap focus and return it when closed (Radix does this; verify).
- Status changes are announced through `aria-live="polite"` (tracker, board).
- Colour is never the only signal: every status has an icon and text.
- Contrast is at least 4.5:1 (check orange text on white; use `brand-dark` for small text).
- Drag-and-drop has a keyboard alternative (the buttons, plus the dnd-kit KeyboardSensor).
- Respect `prefers-reduced-motion`: turn off pulses, confetti and shakes. Use colour and text changes instead.
- Touch targets are at least 44px (student) and 56px (staff).
- Add `@axe-core/playwright` checks to every E2E page visit.

## 9. Performance Budgets
| Metric | Budget | How |
|---|---|---|
| Student initial JS | ≤ 180 KB gzip | Lazy-load role routes. Recharts, dnd-kit and Howler stay out of the student chunk |
| LCP (Moto G-class, 4G) | < 2.5s | Preload Inter, compress images, add `fetchpriority="high"` on the first canteen image |
| CLS | < 0.05 | Fixed image aspect ratios, skeletons that match the final size |
| INP | < 200 ms | Memoized tickets, a single shared timer, virtualized long lists (`@tanstack/react-virtual`) |
| Kitchen board with 40 tickets | ≥ 50 fps while dragging | React Profiler check |
- `rollup-plugin-visualizer` report on every build, with a CI check that fails if the student chunk exceeds the budget.
- Images: request sized variants (`?w=400`) if the backend or CDN supports them, otherwise compress on upload.

## 12. Deployment (Vercel)
1. Import the repo → **Root directory** `apps/web` · framework Vite · build `npm run build` · output `dist`.
2. Environment variables for Preview and Production: `VITE_API_URL`, `VITE_WS_URL` (use `https://…`; Socket.io upgrades to `wss`), `VITE_RAZORPAY_KEY_ID` (test key on Preview, live key on Production), `VITE_SENTRY_DSN`, `VITE_USE_MOCKS=false`.
3. `vercel.json`:
   ```json
   {
     "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }],
     "headers": [
       { "source": "/sw.js", "headers": [{ "key": "Cache-Control", "value": "no-cache" }] },
       { "source": "/assets/(.*)", "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] },
       { "source": "/(.*)", "headers": [ { "key": "Content-Security-Policy", "value": "…see §7…" }, { "key": "X-Content-Type-Options", "value": "nosniff" } ] }
     ]
   }
   ```
4. Ask Member 1 to set **CORS** to allow the Vercel domains with `credentials: true`, and set cookies to `SameSite=None; Secure` if the API is on a different domain.
5. Every pull request gets a preview URL; use it for review and E2E.
6. Smoke test after deploy: log in as each role, check the socket shows 🟢, run a Razorpay test payment, and confirm the PWA installs.

## 13. Acceptance Criteria (Definition of Done for the whole frontend)
- [ ] Lighthouse mobile on `/student`: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, PWA installable.
- [ ] Airplane mode: the app opens, the menu is browsable, the cart works, the pickup code is visible, and ordering is clearly disabled.
- [ ] The chaos tests (§5.9) all end in the correct state. The kitchen never misses an order after reconnecting.
- [ ] An update prompt appears after deploy. It never auto-reloads on the kitchen board.
- [ ] No sensitive values appear in Sentry events (verified with a test event).
- [ ] The CSP doesn't break Razorpay (test payment succeeds in production).
- [ ] CI is green: lint, types, unit, build, E2E. The student bundle is within budget.
- [ ] Production and preview URLs are live. CORS and cookies work across domains.
