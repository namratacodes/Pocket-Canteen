# Phase 5 — Admin Portal & Staff Analytics

> **Project context (all you need to know):** Pocket Canteen runs 5+ independent campus canteens on one platform. A **Platform Admin** onboards each canteen manually (details, FSSAI food-licence number, hours, and the Razorpay account that payments go to directly) and creates **staff logins** for it. When a student cancels an order, the money goes back to their **campus wallet**, not their bank. That money may later be spent at a *different* canteen, so canteens owe each other money every month. For each canteen:
> - **Credit Issued** = refunds created from orders originally paid to this canteen (it holds cash for food it never cooked)
> - **Credit Redeemed** = wallet money spent on food this canteen cooked (it cooked food without receiving cash)
> - **Net Δ = Redeemed − Issued**. A positive Δ means the canteen **receives** money; a negative Δ means it **pays**.
> - Conservation check: **Σ Δ (all canteens) + unspent floating wallet credit = 0**
>
> Member 3's ML service produces **analytics**: peak hours, top dishes, a next-day demand forecast (the "prep sheet"), a **Menu Engineering Matrix** (Stars = high volume and high margin, Plowhorses = high volume and low margin, Puzzles = low volume and high margin, Dogs = low volume and low margin), frequent combos, and ETA accuracy. The backend proxies all of it.
>
> **This phase builds the admin portal and the staff analytics page.**

## 3. Data Contract

```ts
// Admin
export interface AdminCanteen {
  id: string; name: string; location: string; isOpen: boolean;
  fssaiLicenseNo: string;
  operatingHours: Record<'mon'|'tue'|'wed'|'thu'|'fri'|'sat'|'sun', { open: string; close: string; closed: boolean }>;
  imageUrl?: string;
  payment: { razorpayAccountRef: string; bankAccountLast4: string; kycStatus: 'pending'|'verified'|'rejected' };
  stats: { ordersToday: number; gmvToday: number; activeOrders: number; staffCount: number };
  createdAt: string;
}
export type CreateCanteenInput = Omit<AdminCanteen, 'id'|'stats'|'createdAt'|'isOpen'>;
export interface StaffAccount { id: string; name: string; email: string; phone: string; canteenId: string; canteenName: string; status: 'active'|'disabled'; createdAt: string; lastLoginAt?: string }
export interface CreateStaffResponse { staff: StaffAccount; tempPassword: string }   // shown ONCE

export interface SettlementRow {
  id: string; canteenId: string; canteenName: string;
  creditIssued: number; creditRedeemed: number; netPayable: number;   // Δ
  status: 'pending'|'settled'; settledAt?: string; recordedBy?: string;
}
export interface SettlementReport {
  period: string;                         // "2026-09"
  rows: SettlementRow[];
  floatingCredit: number;                 // unspent wallet balances
  transfers?: { from: string; to: string; amount: number }[];  // optional, otherwise computed on FE
}
export interface SettlementEntry { orderUid: string; type: 'issued'|'redeemed'; amount: number; date: string; studentMasked: string }
export interface AdminOverview { activeCanteens: number; ordersToday: number; gmvToday: number; floatingCredit: number; pendingSettlements: number; alerts: { id: string; level: 'warn'|'error'; message: string; at: string }[] }

// Analytics (Member 3 via backend)
export interface PeakHour { hour: number; orders: number; revenue: number }
export interface TopDish { menuItemId: string; name: string; qty: number; revenue: number }
export interface ForecastRow { menuItemId: string; name: string; predicted: number; low: number; high: number }
export interface MatrixPoint { menuItemId: string; name: string; volume: number; margin: number; quadrant: 'star'|'plowhorse'|'puzzle'|'dog'; suggestion: string }
export interface ComboRule { items: string[]; support: number; confidence: number; lift: number }
export interface EtaAccuracy { points: { date: string; predictedAvg: number; actualAvg: number }[]; mae: number }
export interface Kpis { orders: number; revenue: number; avgPrepMins: number; cancelRate: number }
```

|---|---|
| `GET /admin/overview` | KPI cards + alerts |
| `GET /admin/canteens` · `GET /admin/canteens/:id` | List / detail |
| `POST /admin/canteens` | Create (`409 DUPLICATE_FSSAI`) |
| `PATCH /admin/canteens/:id` | Edit |
| `GET /admin/staff?canteenId=` · `POST /admin/staff` → `CreateStaffResponse` (`409 EMAIL_EXISTS`) | |
| `POST /admin/staff/:id/reset-password` → `{tempPassword}` · `PATCH /admin/staff/:id {status}` | |
| `GET /admin/settlements?period=YYYY-MM` → `SettlementReport` | |
| `GET /admin/settlements/:id/entries` → `SettlementEntry[]` | Drill-down |
| `POST /admin/settlements/:id/settle` | Mark settled |
| `GET /analytics/kpis?canteenId=&range=today|7d|30d` | Staff calls get the canteen from the JWT; admin passes it |
| `GET /analytics/peak-hours` · `/top-dishes` · `/forecast?date=` · `/menu-matrix` · `/combos` · `/eta-accuracy` | Same params |

### 4.6 Settlements (`/admin/settlements`)
```text
Period [ September 2026 ▼ ]                                [Export CSV]
┌──────────────┬──────────────┬────────────────┬──────────────────┬─────────┐
│ Canteen      │ Credit issued│ Credit redeemed│ Net Δ            │ Status  │
│ Main Canteen │ ₹4,200       │ ₹6,100         │ +₹1,900  receives│ Pending │
│ Juice Corner │ ₹2,800       │ ₹900           │ −₹1,900  pays    │ Pending │
│ South Hub    │ ₹1,000       │ ₹1,000         │ ₹0               │ Settled │
└──────────────┴──────────────┴────────────────┴──────────────────┴─────────┘
✅ Balanced: Σ Δ (₹0) + floating credit … = 0         ← red ❌ "Mismatch ₹X — contact backend" if not
Who pays whom
  Juice Corner  ──₹1,900──▶  Main Canteen      [Mark both settled]
```
- **Conservation check:** use exactly the rule the backend defines. Show ✅ if `Math.abs(sum + floatingCredit) < 0.01`, otherwise a red ❌ banner. (**Confirm the exact sign convention with Member 1**; show their `balanced` flag if they provide one.)
- **Who pays whom:** use `transfers` if provided, otherwise compute greedily on the frontend:
  ```ts
  const debtors = rows.filter(r => r.netPayable < 0).map(r => ({ n: r.canteenName, a: -r.netPayable })).sort((a,b)=>b.a-a.a);
  const creditors = rows.filter(r => r.netPayable > 0).map(r => ({ n: r.canteenName, a: r.netPayable })).sort((a,b)=>b.a-a.a);
  // two-pointer: transfer min(d.a, c.a) from d to c, decrement both, advance whichever hits 0
  ```
- A row click opens a right-side `Sheet` listing `SettlementEntry` rows (issued vs redeemed, order UID, amount, date).
- **Mark settled** → confirm → `POST settle` → the status badge turns green with "by Admin, 5 Oct".
- **Export CSV** via papaparse: `canteen,issued,redeemed,net,status`.
- Δ colours: green for positive ("receives"), red for negative ("pays"), grey for zero.

| Card | Chart | Detail |
|---|---|---|
| KPIs | 4 stat cards | Show a delta vs the previous period if provided |
| Peak hours | `BarChart` | X axis `8 AM…10 PM`. Bars above the 75th percentile are coloured orange ("rush") |
| Top dishes | Horizontal `BarChart` | Top 10. Toggle between quantity and revenue |
| Prep sheet | Table | `predicted` in bold, range in grey. **Print** uses `@media print` to show only this card, titled "Prep sheet — Main Canteen — Tue 6 Oct" |
| Menu matrix | `ScatterChart` + `ReferenceLine` at the median x/y | Quadrant colours: star `#F59E0B`, plowhorse `#2563EB`, puzzle `#A855F7`, dog `#64748B`. A legend explains the action for each quadrant |
| Combos | List | Sorted by confidence. Shows support/confidence/lift as small chips |
| ETA accuracy | `LineChart` with 2 lines | MAE badge: green if < 2.5 min, otherwise amber |
- **Every card is independent:** its own query, skeleton, and error state ("Forecast unavailable — ML service offline", Retry). One failing card never breaks the page.
- `ResponsiveContainer` everywhere. Number formatting is `en-IN`.
- The Recharts bundle is lazy-loaded with the route.
