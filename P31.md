# Phase 4 — Staff Kitchen Board, Pickup Verification & Menu Control

> **Project context (all you need to know):** Pocket Canteen is a campus pre-ordering platform. Each canteen's staff run a **Kitchen Board** on a landscape tablet or counter monitor. Paid orders arrive in real time over Socket.io. Staff move each order **New → Preparing → Ready**. When the student arrives, they say their **token** (`A-14`, public) and their **4-digit pickup code** (private). Staff enter the code. The backend checks it against a stored hash and marks the order `completed`. After **5 wrong attempts**, the order locks. Staff can also **cancel** an order with a reason (the student gets a wallet refund) and mark menu items **sold out**, which updates student menus live. A staff account belongs to exactly **one canteen** (`canteenId` in the JWT).
>
> Backend statuses: `placed`, `queued`, `preparing`, `ready`, `completed`, `cancelled`. **Board column mapping:** `placed` (paid) and `queued` go in **New**, `preparing` in **Preparing**, `ready` in **Ready**. `completed` and `cancelled` leave the board.

**In scope:** Kitchen Board (3 live columns, ticket cards, buttons and drag-and-drop, transition rules, optimistic updates and rollback, timers, item summary, multi-device sync, connection banner, polling fallback) · Audio alerts (autoplay unlock, debounce, nag mode, mute) · Wake Lock and fullscreen · **Pickup Verification modal** (PIN pad, attempts, lockout) · **Staff Cancel dialog** · **Menu Manager** (availability toggles, canteen open/close).

## 3. Data Contract

```ts
export interface KitchenOrder {
  id: string; orderUid: string; tokenNo: string;
  status: 'placed' | 'queued' | 'preparing' | 'ready' | 'completed' | 'cancelled';
  paymentStatus: 'paid' | 'pending' | 'failed' | 'refunded_to_wallet';
  studentName: string;                          // "Shubh K." (first name + initial)
  items: { menuItemId: string; name: string; quantity: number; isVeg?: boolean; station?: string }[];
  totalAmount: number;
  estimatedPrepSeconds: number | null;
  createdAt: string; preparingAt?: string; readyAt?: string; updatedAt: string;
  verifyAttemptsLeft: number;                   // 5 → 0
  isLocked: boolean;
  note?: string;
}
export interface StaffMenuItem { id: string; name: string; category: string; price: number; isAvailable: boolean; isVeg: boolean; updatedBy?: string; updatedAt: string }
```

| Endpoint | Request | Success | Errors |
|---|---|---|---|
| `GET /kitchen/orders` | – (canteen comes from the JWT) | `KitchenOrder[]` (paid, non-terminal) | – |
| `GET /kitchen/summary` | – | `{ ordersToday, avgPrepMins, isRush }` | – |
| `PATCH /orders/:id/status` | `{ to: 'preparing' | 'ready' }` | `KitchenOrder` | `409 INVALID_TRANSITION` (someone else moved it), `404` |
| `POST /orders/:id/verify-pickup` | `{ code: "4721" }` | `{ order: KitchenOrder }` (completed) | `422 PICKUP_CODE_INVALID {attemptsLeft}`, `423 PICKUP_LOCKED`, `429 RATE_LIMITED {retryAfterSec}`, `409 NOT_READY` |
| `POST /orders/:id/override-pickup` | `{ managerPin }` | `{ order }` | `403` (**confirm with Member 1**) |
| `POST /orders/:id/cancel` | `{ reason: string }` | `{ order, refundedAmount }` | `409 NOT_CANCELLABLE` |
| `GET /kitchen/menu` | – | `StaffMenuItem[]` | – |
| `PATCH /menu-items/:id` | `{ isAvailable }` | `StaffMenuItem` | – |
| `PATCH /canteens/me` | `{ isOpen }` | `{ isOpen }` | – |

**Socket** (room `canteen:${canteenId}`, joined automatically by the server from the JWT, or explicitly with `room:join`):
| Event | Payload | Board reaction |
|---|---|---|
| `order:new` | `KitchenOrder` | Add to New (dedupe by id), play the sound, pulse for 10s |
| `order:status_changed` | `{ orderId, from, to, order }` | Move the card. Terminal statuses remove it (with an exit animation) |
| `order:cancelled` | `{ orderId, reason, cancelledBy }` | Strike-through for 2s, then remove |
| `order:pickup_locked` | `{ orderId }` | 🔒 badge on the card |
| `menu:availability_changed` | `{ menuItemId, isAvailable }` | Patch the menu manager cache (sync across tablets) |

**Stale guard:** ignore the event if `order.updatedAt < cached.updatedAt`.

- `GET /kitchen/orders` → `useQuery(['kitchen', canteenId])`. All socket events patch this same cache.
- The empty column state says "No orders ☕" (New), "Nothing cooking" (Preparing), "No pickups waiting" (Ready).

### 4.2 OrderTicket
- Token in mono `text-3xl`, then items (quantity in bold, veg dot), student name, timer, primary action button (**at least 56px tall, full width**), and a ⋮ menu (Cancel order, View details).
- Badges: 🆕 pulse (first 10s) · 🔒 Locked · ⚠ Overdue.
- `React.memo` keyed on `order.updatedAt` plus the tick bucket, to avoid needless re-renders.

**Timer rules (one shared `useNow(1000)` hook for the whole board):**
| Column | Shows | Amber | Red |
|---|---|---|---|
| New | "received X ago" from `createdAt` | > 2 min not started | > 5 min |
| Preparing | `elapsed / ETA` + progress bar from `preparingAt` | > 80% of ETA | > 100% → "OVERDUE +2m", red border |
| Ready | "waiting X" from `readyAt` | > 5 min | > 10 min |

### 4.3 Moving orders: buttons and drag-and-drop
**Transition rules (UI mirrors backend):**
| From column → To | Allowed | How |
|---|---|---|
| New → Preparing | ✅ | "Start Cooking" button or drag |
| Preparing → Ready | ✅ | "Mark Ready" button or drag |
| Ready → done | ❌ by drag | **Only through the Verify Pickup modal** |
| Skipping a column / moving backwards | ❌ | The drop zone shows a red dashed outline and a "Not allowed" tooltip, and the card snaps back |

dnd-kit setup: `PointerSensor` (activation distance 8px, so taps still hit buttons), `TouchSensor` (delay 150ms), and `KeyboardSensor` (for accessibility). Each column is a `useDroppable`. While dragging, a `DragOverlay` shows a tilted card.

**Optimistic mutation with rollback**
```ts
const move = useMutation({
  mutationFn: ({ id, to }: { id: string; to: 'preparing'|'ready' }) => api(`/orders/${id}/status`, { method: 'PATCH', json: { to } }),
  onMutate: async ({ id, to }) => {
    await qc.cancelQueries({ queryKey: key });
    const prev = qc.getQueryData<KitchenOrder[]>(key);
    qc.setQueryData<KitchenOrder[]>(key, (l) => l!.map(o => o.id === id ? { ...o, status: to, [to === 'preparing' ? 'preparingAt' : 'readyAt']: new Date().toISOString() } : o));
    return { prev };
  },
  onError: (e: ApiError, _v, ctx) => {
    qc.setQueryData(key, ctx!.prev);
    toast.error(e.code === 'INVALID_TRANSITION' ? 'Already moved by another device' : 'Update failed — try again');
  },
  onSuccess: (order) => qc.setQueryData<KitchenOrder[]>(key, (l) => l!.map(o => o.id === order.id ? order : o)),
});
```
- **Mark Ready** shows a small 3s toast: "A-12 is Ready · student notified".
- **Multi-device:** two tablets stay identical because both receive `order:status_changed`. If an event arrives for the card being dragged, it's queued and applied after the drop.

### 4.4 Board extras
- **Items summary drawer (`≡ Items`):** aggregates every New + Preparing item → `8× Samosa · 5× Masala Chai · 3× Masala Dosa`, sorted by quantity, so cooks can batch.
- **Fullscreen (`⛶`):** `document.documentElement.requestFullscreen()`.
- **Wake Lock:** `navigator.wakeLock?.request('screen')`, requested again on `visibilitychange`, so the tablet never sleeps.
- **Connection banner:** when not connected, a full-width red bar says *"Connection lost — new orders may not appear. Reconnecting…"*, and the board polls `GET /kitchen/orders` every 10s. On reconnect, refetch and diff: orders that weren't there before trigger the new-order sound once.
- **Prefs (`kitchenPrefsStore`, persisted):** `soundOn`, `nagMode`, `density: 'comfortable'|'compact'`, `fontScale`.

## 5. Audio Alerts (`lib/audio/audioService.ts`)
1. **Autoplay unlock:** when the board mounts, show a full-screen overlay: **"👋 Tap to start your shift"**. That tap calls `Howler.ctx.resume()`, plays a silent sound, requests the Wake Lock, and dismisses the overlay.
2. `order:new` → `playNew()` (debounced 1.5s: 5 orders in a burst produce one sound) + the tab title shows `(3) New orders` until focus.
3. **Nag mode:** every 60s, if any New ticket is more than 2 min old, play a softer `ding`.
4. Ready set from another device → optional `ding`.
5. Muted (`soundOn=false`) → no sound, but the visual pulse and title flash still happen.
6. A volume slider in the sound popover.

## 6. Pickup Verification Modal
Opened from the top bar **"Verify Pickup"** (pick a token) or from a Ready card's **"Verify & Hand Over"** (token prefilled).
```text
┌───────────────────────────────────────┐
│ Verify Pickup                       ✕ │
│ Token  [ A-09                    ▼ ]  │  combobox of READY tokens, type-to-search
│ 1× Cold Coffee · 1× Veg Sandwich      │
│ Riya S. · ₹110                        │
│                                       │
│ Ask the student for their 4-digit code│
│       ┌──┐ ┌──┐ ┌──┐ ┌──┐             │
│       │4 │ │7 │ │  │ │  │             │
│       └──┘ └──┘ └──┘ └──┘             │
│   ┌─────┬─────┬─────┐                 │
│   │  1  │  2  │  3  │                 │  PinPad, 72px keys
│   │  4  │  5  │  6  │                 │
│   │  7  │  8  │  9  │                 │
│   │  ⌫  │  0  │ Clr │                 │
│   └─────┴─────┴─────┘                 │
│ Attempts left: 5                      │
└───────────────────────────────────────┘
```
**States**
| State | Trigger | UI |
|---|---|---|
| Entering | default | Digits fill in. The physical keyboard (0–9, Backspace) also works |
| Submitting | 4th digit entered → auto `POST verify-pickup` | Spinner, PIN pad disabled |
| ✅ Success | 200 | Full green panel "Hand over A-09 ✅" with the item list for 1.5s → close → card exits Ready |
| ❌ Wrong | 422 `{attemptsLeft}` | Boxes shake (CSS keyframes), clear, refocus. "Incorrect · 3 attempts left" (red when 1 is left) |
| 🔒 Locked | 423 or attemptsLeft = 0 | Red panel "A-09 locked after 5 failed attempts. Manager override required." + **[Manager override]** (PIN → `override-pickup`), plus the card gets a 🔒 badge |
| ⏳ Rate-limited | 429 | "Too many attempts — wait 30s" countdown, PIN pad disabled |
| Not ready | 409 | "This order isn't marked Ready yet" |

The code is held in local component state only, is cleared on close, and is never logged.

## 11. Acceptance Criteria
- [ ] A new order appears within 1s, plays **one** sound per burst, and pulses. Duplicate events never create two cards.
- [ ] Buttons and drag-and-drop both work on touch (iPad Safari, Android Chrome) and by keyboard. Illegal drops snap back.
- [ ] A failed PATCH rolls back with a toast. A second tablet reflects moves within 1s.
- [ ] Timers change colour at the thresholds. Overdue shows a red border.
- [ ] The verify modal covers success, wrong code (shake + attempts), lock, 429 countdown, and not-ready. The code is never logged.
- [ ] Cancel requires a reason. The "also mark sold out" option works.
- [ ] The menu toggle reflects on a student menu tab live. The canteen close switch asks for confirmation.
- [ ] The shift-start overlay unlocks audio. The screen doesn't sleep for 10 min (Wake Lock). Mute still shows visual flashes.
- [ ] Socket drop → red banner + polling. Reconnect → orders missed in between appear.
- [ ] The board stays smooth (≥ 50 fps while dragging) with 40 tickets.
